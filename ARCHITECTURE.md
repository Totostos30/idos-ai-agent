# Архитектура IDOS

Этот документ описывает исходное приложение и основные границы компонентов. Версию сверяйте с `core/config.py`; тест `tests/test_version.py` проверяет её согласованность с манифестами и документацией.

## Слои приложения

```text
Start-IDOS.bat / scripts/Start-IDOS.ps1
        │
        ├── GigaSTT (необязательный локальный процесс, 127.0.0.1:9876)
        │
        └── Tauri 2 / Rust оболочка
              ├── остров, основное окно, окно выбора области
              ├── системный трей и глобальные сочетания клавиш
              └── запускает Python: python -m core
                         │
                         ├── CoreServer: HTTP + WebSocket на 127.0.0.1
                         ├── Agent → Router → провайдер модели
                         ├── реестр инструментов и сценарии UI Automation
                         ├── SQLite, настройки, память, навыки, MCP
                         └── голосовые и фоновые функции

Frontend (Vite/JavaScript) ── WebSocket RPC/events ── Python CoreServer
```

В `data/runtime/core.json` ядро записывает актуальные порт и случайный токен соединения. Интерфейс вызывает Tauri-команду `core_info`, затем соединяется по `ws://127.0.0.1:<port>/ws?token=...`. RPC-запросы используют поля `id`, `method`, `params`; события ядра рассылаются подписанным окнам. HTTP-обработчик `/health` используется для локальной проверки состояния.

| `tests/` | Модульные и интеграционные проверки ядра |

## Жизненный цикл

1. `Start-IDOS.ps1` задаёт корень проекта; при наличии `tools\gigastt\bin\gigastt.exe` и свободного порта запускает локальное распознавание речи.
2. В режиме разработки запускается `npm run tauri dev`; Tauri создаёт окна, трей и глобальные сочетания клавиш.
3. Rust-оболочка запускает `python -m core` из виртуального окружения проекта.
4. `core.app.App` инициализирует настройки, SQLite, DPAPI-ориентированное хранилище ключей, роутер моделей, память, навыки, MCP, браузер, STT/TTS, сценарии и инструменты.
5. Ядро поднимает локальный сервер и записывает runtime-метаданные; интерфейс подключается к WebSocket и обменивается RPC-командами и событиями.
6. При остановке ядро закрывает фоновые задачи, серверы и базу данных. Оно также следит за процессом родительской Tauri-оболочки.

В демо-режиме часть Windows-специфичных действий и фоновых функций не запускается.

## Цикл агента и инструменты

Агент подготавливает контекст и историю, выбирает доступные описания инструментов в рамках бюджета модели, вызывает инструмент, сохраняет результат и продолжает план до ответа, остановки или лимита шагов/времени. Реестр в `core/tools/__init__.py` задаёт схемы, действия, доступность и категории `read`, `act`, `danger`; фактическое подтверждение зависит от `agent.autonomy`.

Команды shell выполняются отдельными процессами PowerShell/cmd/Python и не являются песочницей. Сценарии хранятся в `data/scenarios/`, могут использовать готовые блоки и запускаться по пользовательским фразам-триггерам.

## Данные и зависимости

- `data/`: настройки, SQLite-база, ключи, пользовательские навыки, сценарии, заметки, история буфера обмена и локальный профиль браузера.
- `logs/`: обычные и аварийные логи.
- `models/`, `tools/`: модели и дополнительные исполняемые компоненты (например, Silero, GigaSTT и ffmpeg).
- `.venv/`, `node_modules/`, `dist/`, `src-tauri/target/`: зависимости и артефакты сборки.

Пользовательские каталоги и крупные локальные файлы исключаются из Git через `.gitignore`; это не заменяет проверку уже отслеживаемых файлов и истории коммитов. Подробности — [SECURITY.md](SECURITY.md).

## Технологический стек

- Python 3.11 и `asyncio` для ядра и локального сервера.
- JavaScript/CSS и Vite для webview-интерфейса.
- Rust, Tauri 2 и Win32 API для desktop-оболочки.
- SQLite для пользовательской истории и локальных структурированных данных.
- Playwright для браузерного управления; Windows UI Automation/WinRT/WASAPI для системных функций.
- OpenAI-compatible chat-completions API для облачных моделей; локальные OpenAI-compatible endpoints могут быть настроены пользователем.

## Проверки и сборка

```powershell
.venv\Scripts\python -m unittest discover -s tests
npm run build
cd src-tauri; cargo check --locked; cd ..
powershell -ExecutionPolicy Bypass -File scripts\Build-Release.ps1
```

CI в `.github/workflows/ci.yml` выполняет Python-тесты на Windows, сборку Vite и `cargo check --locked`. Сборка `Build-Release.ps1` создаёт переносимый комплект и ZIP, а не полностью автономный установщик: после распаковки нужно подготовить зависимости через `scripts\Setup.ps1`.
